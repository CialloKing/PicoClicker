# v0.4.5 之后的反汇编体积分析

基线为 v0.4.5（`92854bb`），候选代码为 `a86ee90`。四份基线 EXE 均通过该版本的 SHA-256 校验。使用同一套 clang-cl 22.1.8、LLD 22.1.8 和 Windows SDK 10.0.28000.0 重新构建，基线成品仅链接时间戳有差异。

| 版本 | 基线 EXE | 候选 EXE | 基线 → 候选 `.text` 有效字节 |
| --- | ---: | ---: | ---: |
| 普通 x64 | 8,704 | **8,192** | 4,390 → 4,086 |
| 普通 x86 | 7,168 | 7,168 | 3,496 → 3,432 |
| Lite x64 | 5,120 | 5,120 | 1,958 → 1,942 |
| Lite x86 | 4,096 | 4,096 | 1,464 → 1,464 |

普通 x64 的代码减少 304 字节，越过 4,096 字节边界，使磁盘上的代码节少占 512 字节。成品由 512 字节文件头、4,096 字节代码和 3,584 字节只读资源节组成。`.data` 的 1,184 字节由加载器零填充。

## 哪些改动有效

以下每项都单独应用于普通 x64 基线，再使用项目打包脚本测量。函数排列、分支距离和节对齐会随组合改变。

| 单项对照 | `.text` 减少字节 | 打包后 EXE |
| --- | ---: | ---: |
| 用 `BT` 在 32 字节位图中检查虚拟键 | 64 | 8,704 |
| 用 `REP MOVSW` 复制已知长度的 UTF-16 配置路径 | 32 | 8,704 |
| 一次比较 `WM_COMMAND` 的控件 ID 和通知码 | 32 | 8,704 |
| 复用启用控件的调用循环 | 16 | 8,704 |
| 将路径校验保留为独立函数 | 32 | 8,704 |
| 调整 LLVM 的循环不变量外提和条件分支合并两项设置 | 112 | 8,704 |
| 复用 192 字节的 x64 加载配置及其较小的支持代码 | 32 | 8,704 |
| 另写汇编叶函数，共享两处十六进制格式化 | 32 | 8,704 |
| 将共享的 `SendDlgItemMessageW` 换为四个专用控件 API | 64 | **9,216** |

四个专用控件 API 增加了导入数据，打包后的只读节从 3,572 增至 3,644 字节，越过 3,584 字节边界。候选保留共享的控件 API 和原有十六进制格式化。在候选上改用共享的 C 格式化函数或内联汇编，两种做法都得到 4,070 字节的代码节，EXE 均为 8,192 字节。x86 的按键范围判断仍能给只读节尾部的重定位表留出空间。

在候选普通 x64 的反汇编中，RVA `0x1154` 的 `bt dword ptr [rcx], edx` 检查队列消息中的主键，`0x1393` 的 `rep movsw` 复制路径，`0x151c` 和 `0x1529` 直接比较两个按钮的命令。可用 `llvm-objdump -d -M intel` 和 x64 构建目录的 `PicoClicker.map` 核对。Windows 将控件 ID 和通知码放在同一个参数的低字和高字中。[WM_COMMAND](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-command)

## 再省 512 字节需要多少

按候选的节布局计算，下表给出单独压缩某一节时，需要减少的有效字节数。不同节各有自己的 512 字节对齐边界。[PE 节表](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#section-table-section-headers)

| 版本 | 从 `.text` 省 | 从 `.rsrc` 省 |
| --- | ---: | ---: |
| 普通 x64 | 502 | **296** |
| 普通 x86 | 360 | 280 |
| Lite x64 | 406 | 448 |
| Lite x86 | 440 | 512 |

- 普通 x64 的 `.rsrc` 实占 3,368 字节。导入描述符、两套指针表、DLL 名和函数名等共占 1,494 字节，窗口与清单所在的完整资源树占 792 字节。下一轮可以先核对哪些 Win32 调用能复用，并把新增指令和减少的导入数据一起计量。
- 如果继续写汇编，普通 x64 的 `DialogProc` 和 `Run` 分别占 970 和 654 字节，边界来自 PE 展开表。优先比较这两处的消息分派、寄存器保存和调用准备。仅改写短小的格式化函数，在本次对照里最多省了几十字节。

## 验证范围

四份成品均通过打包校验。逐项核对导入函数、对话框和清单内容、重定位以及 x64 展开表。x64 实际加载后，CFG 调度指针已由系统填入，栈 Cookie 已初始化。按键位图的 256 个值逐个对照了原判断。

界面测试在后台隔离桌面运行，使用代码节与成品相同、清单设为 `asInvoker` 的副本。覆盖间隔校验、按钮启停、控件启用状态、F1 冲突、普通版改键与重启恢复，以及含非 BMP 字符的 250/251 个 UTF-16 码元配置路径边界。启停测试使用 60,000 ms 间隔，在首个定时信号前停止。实际鼠标事件、CPS 和管理员会话交互尚待复测。

## 实验版第二轮

以 `437f704` 为基线，使用 clang-cl 22.1.8、LLD 22.1.8 和 Windows SDK 10.0.28000.0。常规版和 Lite 的文件大小取打包成品，实验版取 `PicoClickerExperimental` 目标的输出。

| 版本 | EXE 字节 | `.text` 有效字节 |
| --- | ---: | ---: |
| 普通 x86 | 7,168 → 7,168 | 3,432 → 3,400 |
| 普通 x64 | 8,192 → 8,192 | 4,086 → 4,054 |
| Lite x86 | 4,096 → 4,096 | 1,464 → 1,416 |
| Lite x64 | 5,120 → 5,120 | 1,942 → 1,846 |
| 实验 x86 | 4,024 → **3,784** | 1,464 → 1,224 |
| 实验 x64 | 5,014 → **4,710** | 1,942 → 1,638 |

- 用一个计数器记录启停状态和代次。仅做这一项，Lite x86 的代码节少 32 字节，重定位表少 4 字节。按钮和 F1 复用切换路径，鼠标按钮检查复用控件消息调用。
- 把单个布尔辅助函数改为由调用点比较，两种架构的文件大小均持平。把退出进程移入消息循环虽然缩短了代码，却使编译器省掉 `Run` 的栈 Cookie 检查，因此保留原退出路径。
- 实验版将栈 Cookie 的磁盘初值放在只读数据中，使用 PE 子系统版本 6.03，由 Windows 加载器写入 Cookie。入口检查加载结果，无效时终止。实验版由此去掉了 CRT Cookie 初始化所需的四项导入，导入数从 27 降到 23。x86 的重定位表从 184 字节降至 156 字节。
- 上一版已裁掉 x86 的 72 字节末节填充。建议中的 3,944 字节是旧二进制扣除全部可数填充后的算术值，还需满足 Windows 的磁盘与内存映射约束。本轮 x86 达到 3,784 字节，主要收益来自实际代码和导入数据的减少。3,584 字节、3 KiB 与 2,500 字节仍是后续实验目标。

实验 x86 距 3,584 字节还差 200 字节。若保持现有标准布局，Lite x86 单独缩减代码节需要省 392 字节，单独缩减资源节需要省 508 字节，最终文件才会少一个 512 字节块。

四个常规产物通过发布打包检查。两种实验成品均使用 `asInvoker` 副本在 Windows 10 22H2 的隔离桌面验证界面、间隔校验、按钮启停和 F1 冲突。每种架构的两次启动都读到了不同的 Cookie，并确认 CFG 已启用、代码页可执行、可写数据页和资源页不可执行。x64 另外检查了 CFG 调度指针和异常展开表。

## 第三轮导入表和控件编号

本轮以 `e99a43a` 为基线，沿用上一轮工具链。控件编号从 1000–1006 改为 10–16，使部分 x86 的立即数指令变短。导入表在实验目标链接时生成。23 项按名称导入共享 IAT，省去独立 ILT 的 x86 100 字节、x64 200 字节。Hint/Name 条目复用前一个名称的结束字节，保持 Hint 字段的 2 字节对齐。加载器以名称核对 Hint 的结果。[Microsoft PE 导入表规范](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#the-idata-section)

| 实验版 | 上轮 EXE | 仅控件编号 | 完成导入表优化 | 只读资源节有效字节 |
| --- | ---: | ---: | ---: | ---: |
| x86 | 3,784 | 3,736 | **3,736** | 1,896 → 1,752 |
| x64 | 4,710 | 4,710 | **4,198** | 2,288 → 2,040 |

x64 的只读节越过 2,048 字节对齐边界，整个 EXE 少占 512 字节。x86 的只读节在两次测量中均占四个 512 字节块，体积收益来自代码节。当前实验 x86 距 3.5 KiB 还差 152 字节。

`PICOCLICKER_STANDARD_LOADER_COOKIE` 可单独应用于标准布局的普通版和 Lite。启用后普通版从 40 项导入降到 38 项，Lite 从 27 项降到 23 项。四种构建均通过标准打包，代码与只读数据的缩减尚未跨过各自的文件对齐边界。

| 标准布局 | 打包后字节 | 上轮 `.text` | 当前默认 `.text` | 启用加载器 Cookie 的 `.text` |
| --- | ---: | ---: | ---: | ---: |
| 普通 x86 | 7,168 | 3,400 | 3,352 | 3,144 |
| 普通 x64 | 8,192 | 4,054 | 4,038 | 3,830 |
| Lite x86 | 4,096 | 1,416 | 1,368 | 1,176 |
| Lite x64 | 5,120 | 1,846 | 1,830 | 1,638 |

在 Windows 10 22H2 的隔离桌面上，用 `asInvoker` 副本验证了界面、间隔校验、启停和 F1 冲突。普通版另外验证了改键、保存和重启恢复。两个实验版分别核对了 23 个运行时导入地址、CFG、Cookie 和各节权限。对启用加载器 Cookie 的四个标准产物也读取了运行时 Cookie。管理员会话、其他 Windows 版本及安全软件兼容性待验证。

## 实验版 ASCII 界面

本轮以 v0.4.6 发布资产为基线。实验版使用英文控件文字、ASCII 运行时文本和七项 ANSI Win32 导入。导入名的 `A` 与 `W` 后缀等长，主要收益来自短状态文本、单字节数字缓冲区和共用错误提示调用。标准对话框模板以 UTF-16 保存英文标签。[Microsoft 对话框模板规范](https://learn.microsoft.com/windows/win32/api/winuser/ns-winuser-dlgtemplate)

| 实验版 | EXE 字节 | `.text` 有效字节 | 只读资源节有效字节 |
| --- | ---: | ---: | ---: |
| x86 | 3,736 → **3,732** | 1,176 → 1,176 | 1,752 → 1,684 |
| x64 | 4,198 → **4,182** | 1,638 → 1,622 | 2,040 → 1,976 |

x86 将只读节放在文件末尾再裁剪。x64 将代码节放在末尾。只读数据节省的大部分字节落在既有对齐空间内。普通版和 Lite 的四份打包成品与 v0.4.6 逐字节一致，差异仅为链接时间戳。

Windows 10 22H2 的隔离桌面验证了两种实验版的 1、10、50 ms 档左中右键事件、F1 启停、热键冲突和运行中关闭，并检查了加载器 Cookie、CFG、运行时导入地址及各节权限。测试使用仅将清单改为 `asInvoker` 的副本。间隔解析检查控件返回的 ASCII 字节。在 ANSI 代码页 936 上，Windows 将外部传入的 `5000²` 转成 `50002`，程序按界面显示的数字处理。

## 汇编与重定位布局

以 `45503b9` 的 ASCII 实验版为基线，继续用 clang-cl 和 LLD 22.1.8 构建。下表的代码字节取链接后的 `.text`，打包时移入同一节的重定位表另列。

| 实验版 | EXE 字节 | 代码节有效字节 | 基址重定位表 | 打包后只读资源节有效字节 |
| --- | ---: | ---: | ---: | ---: |
| x86 | 3,732 → **3,300** | 1,176 → 1,128 | 152 → 124 | 1,684 → 1,512 |
| x64 | 4,182 → **4,134** | 1,622 → 1,574 | 20 → 20 | 1,976 → 1,944 |

- 将 x86 基址重定位表从只读节末尾搬到代码节原有的填充区，单独让成品从 3,732 降到 3,376 字节。资源节因此占 1,536 字节，代码节放在文件末尾。最终代码节在磁盘上占 1,252 字节，其中 124 字节是重定位表。节的 RVA、页面对齐和权限标志沿用原布局。[Microsoft PE 基址重定位表](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#the-reloc-section-image-only)
- x86 汇编通过一个寄存器访问 IAT，消息队列读完后复用缓冲区读取光标位置。仅替换等待与点击路径时，代码和重定位分别减少 32 和 24 字节，成品为 3,320 字节。改用汇编实现整个启停函数的对照多占 8 字节。
- 实验版退出时由系统回收固定的 F1 注册，导入数从 23 降到 22。尝试改用关闭标记代替 `PostQuitMessage` 时，两种架构的 C 候选各增大 32 字节。x64 在保留当前消息循环结构的前提下单独关闭机器循环不变量外提，再省 32 字节。

四份普通版和 Lite 的打包成品在归一化链接时间戳后与 v0.4.6 逐字节一致。Windows 10 22H2 隔离桌面的实验副本经过了实际点击、F1 冲突及关闭后重新注册、`WM_QUIT` 退出码和栈 Cookie 检查，并在非首选基址核对了 CFG、IAT 和内存页权限。本轮实际点击使用只改动清单的 `asInvoker` 副本。

同桌面交替测试 1 ms 档，每次采样约 1.2 秒。x86 优化前后三次样本分别为 544–558 CPS 和 522–558 CPS，间隔 P99 分别为 6.89–7.56 ms 和 6.76–9.16 ms。x64 单次对照从 532 到 550 CPS，间隔 P99 从 7.65 到 7.13 ms。x86 两组范围重叠，短测不足以确认性能是否回退。

## x64 消息循环与 x86 PE 头

以下结果以 v0.4.7 发布资产为基线，用 clang-cl 和 LLD 22.1.8 构建。代码节字节数取自链接产物，单独列出打包时移动的重定位表。

| 实验版 | EXE 字节 | 代码节有效字节 | 基址重定位表 | 打包后只读资源节有效字节 |
| --- | ---: | ---: | ---: | ---: |
| x86 | 3,300 → **3,160** | 1,128 → 1,112 | 124 → 104 | 1,512 → 1,512 |
| x64 | 4,134 → **3,980** | 1,574 → 1,510 | 20 → 20 | 1,944 → 1,932 |

- v0.4.7 的 x86 IAT 偏移值可以用一个字节表示，但 LLVM 为符号表达式生成了四字节位移。两个汇编版本现在显式编码短位移，并在汇编时检查范围。单改这项让 x86 成品缩至 3,268 字节。
- x86 消息循环从传入的模块基址计算地址，重定位表因此少 20 字节。打包器可在 PE 头内删除三个空的末尾数据目录，并利用腾出的空间存放完整的 104 字节重定位表。节 RVA 和页面权限沿用原布局。`llvm-readobj` 无法直接读取这种重定位表，打包脚本从链接产物重现成品并核对哈希，再用 LLVM 检查链接产物。[Microsoft PE 数据目录规范](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#optional-header-data-directories-image-only)
- x64 汇编复用调用栈的参数区和消息缓冲区，保留 Cookie 检查与异常展开记录。CFG 回调通过 `.gfids$y` 显式标记。1,510 字节代码和 20 字节重定位表可装进 1,536 字节代码节，磁盘末尾改放只读资源节后可裁掉更多填充。[Microsoft x64 异常展开](https://learn.microsoft.com/en-us/cpp/build/exception-handling-x64) [LLD CFG 表实现](https://github.com/llvm/llvm-project/blob/llvmorg-22.1.8/lld/COFF/Writer.cpp#L2029-L2047)
- 解析现有对话框模板确认，七个控件都使用数字类标识。拆分 `Toggle`、替换间隔解析循环和改变鼠标按钮选择分支的候选均未缩小成品。

Windows 10 22H2 使用 `asInvoker` 副本通过了三种鼠标按键、F1 启停、停止后重启、运行中关闭、间隔校验和 `WM_QUIT` 退出码检查。两种架构在非首选基址验证了 CFG、栈 Cookie、导入地址和页面权限。普通版和 Lite 的四份成品除时间戳外与 v0.4.7 一致。管理员会话和其他 Windows 版本待验证。

同一隔离桌面交替测试 1 ms 档，每个版本采样三次，每次约 1.2 秒。x86 的吞吐范围由 627–633 CPS 变为 617–632 CPS，间隔 P99 由 2.82–2.95 ms 变为 2.72–2.95 ms。x64 由 625–626 CPS 变为 623–633 CPS，间隔 P99 由 2.75–2.84 ms 变为 2.81–3.00 ms。短测仅覆盖这台机器。

## 内存对话框与 x86 代码布局

以下结果以 v0.4.8 发布资产为基线，使用 clang-cl 和 LLD 22.1.8。代码节大小取自链接产物，基址重定位表单独统计。

| 实验版 | EXE 字节 | 代码节有效字节 | 基址重定位表 | 打包后只读节有效字节 |
| --- | ---: | ---: | ---: | ---: |
| x86 | 3,160 → 3,044 → **2,984** | 1,112 → 1,016 | 104 → 40 | 1,512 → 1,448 |
| x64 | 3,980 → **3,916** | 1,510 → 1,510 | 20 → 20 | 1,932 → 1,868 |

- x86 汇编让对话框回调、启停和状态更新共用 IAT 与状态寄存器。代码节装进两个 512 字节块后，打包器把只读节放到文件末尾。保存间隔文本的栈帧有 Cookie 检查，Win32 回调目标继续登记在 CFG 表中。
- 两种实验版均通过 `CreateDialogIndirectParamA` 读取 RC 编译出的 298 字节模板，模板与 v0.4.8 的对话框资源逐字节一致。资源目录从 160 缩到 88 字节，保留管理员清单。扣除较长的导入名和对齐后，这一步使 x86 再少 60 字节、x64 少 64 字节。x86 初次改用内存模板时，代码节回涨到 1,032 字节，成品反而变为 3,080 字节。将错误分支移近间隔校验后才恢复对齐收益。[Microsoft 内存对话框 API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createdialogindirectparama)

普通版和 Lite 的四份打包产物除链接时间戳外与 v0.4.8 逐字节一致。Windows 10 22H2 隔离桌面上的 `asInvoker` 副本通过了左中右键实际点击、F1 启停与冲突处理、间隔校验、快速重启、运行中关闭和 `WM_QUIT` 退出码验证。两种架构在非首选基址核对了 CFG、栈 Cookie、运行时导入和页面权限，x64 还检查了异常展开记录。管理员会话和 Windows 11 待实测。

## v0.4.14 后续反汇编与体积实测

以已发布的 v0.4.14 实验版为基准。下表按各架构的实验顺序记录打包后 EXE 大小。

| 步骤 | x86 | x64 |

- 两种架构继续使用原来的 151 B 编码。当前模板只有六个可用单字节编码替换的常见样式字和四组连续三个零字，评估新增解码指令后可节省的空间有限。

六份候选通过打包及 SHA-256 核对。普通版和 Lite 除链接时间戳外与 v0.4.14 一致。Windows 10 22H2 隔离桌面实测了 144 DPI、1／10／50 ms 档左中右键点击、运行中编辑、快速重启、关闭、F1 启停与占用恢复，以及 `WM_QUIT` 退出码。两种架构均在非首选基址核对了实际导入、CFG、栈 Cookie、节区权限和解码后的模板。x64 的两个栈帧均通过 `RtlVirtualUnwind` 检查。Windows 11 和管理员会话尚待实测。

交替短测中曾出现采样时长不足和基线焦点变化，两份候选单独重跑均通过。功能验收采用成品的实际键入和点击结果，短测数据未用于判断长期吞吐。

## x86 压到 2 KiB 以内

| x86 候选 | EXE | 只读节实际占用 | 代码节实际占用 |
| --- | ---: | ---: | ---: |
| 上一轮候选 | 2,142 B | 606 B | 1,024 B |
| 压缩运行入口、回调寄存器保存与错误路径 | 2,086 B | 550 B | 1,024 B |
| 合并关闭路径，复用解码后的零值参数 | 2,042 B | 512 B | 1,018 B |

x86 窗口创建后用 EBP 指向消息缓冲区，ESI 持续保留窗口句柄。收到关闭通知时设置退出标志，消息循环在下次点击前退出。进程退出时由系统回收窗口、计时器和 F1 注册。这样可移除 `DestroyWindow` 和 `PostQuitMessage` 两个 x86 导入，外部 `WM_QUIT` 的退出码仍照常传递。

两个零参数复用解码结束后的 ECX，回调提前跨过一个 16 字节对齐边界。只读节有效长度降到 510 B，磁盘只需一个 512 B 块。打包器把代码节放在末尾并裁掉填充，最终占 1,018 B。PE 文件头仍占 512 B，页面对齐、ASLR、DEP、CFG 和栈保护沿用原配置。

Windows 10 22H2 实测包含两种架构的 144 DPI 界面、左中右键实际点击、运行中编辑、快速重启、F1 启停与冲突恢复、运行中关闭，以及 `WM_QUIT` 退出码。额外检查了非首选基址、导入、栈 Cookie、CFG、页面权限和 x64 异常展开。Windows 11 和管理员会话尚待实测。

## Lite 的标准对齐优化

以 v0.4.16 的 Lite 成品为基准。下表为 clang-cl 22.1.8 与 LLD 构建后的打包体积。

| 步骤 | x86 | x64 |

v0.4.17 采用上表的最终布局。

- x64 的代码节和资源节各少占一个 512 B 文件块。打包后两个节的有效长度分别为 1,480 B 和 1,904 B。
- x86 的资源和常量合计 1,530 B，可装进三个文件块。将原样的 148 B 重定位表搬入代码节现有填充后，代码节有效长度为 1,308 B。尝试复用 x64 的额外编译选项，x86 打包成品仍为 3,584 B。以现有节分配继续缩到 3,072 B，还要让代码与重定位表合计少占至少 284 B。

- Lite 的导入从 27 项降到 20 项。加载器负责初始化栈 Cookie。关闭时由消息循环退出，由进程退出回收对话框、计时器和 F1 热键。外部 `WM_QUIT` 继续传递退出码。

Windows 10 22H2 的隔离桌面使用仅改动清单的 `asInvoker` 副本，实测了 Unicode 界面、144 DPI、数字输入、Tab、方向键、Enter、Esc、控件锁定、1／10／50 ms 左中右键实际点击、快速重启、运行中关闭、F1 启停与冲突恢复、`WM_QUIT` 退出码。两种架构在非首选基址核对了 IAT、CFG、Cookie 和节区权限，x64 的 `Run` 与 `DialogProc` 栈帧通过了 `RtlVirtualUnwind` 检查。六份候选通过打包和 SHA-256 校验，普通版与实验版除链接时间戳外与 v0.4.16 一致。Windows 11 和管理员会话尚待实测。

## v0.4.17 成品反汇编与下一档体积

以 `1b9b7c1` 和本地 `dist/v0.4.17` 的六份成品为基线。六份 SHA-256 均与该版本清单一致。用 release 对象、clang-cl 22.1.8、LLD 和原打包脚本在临时目录重链接，六份对照与成品的唯一差异均为 COFF 时间戳。下表列出各组试验中体积最小的打包结果。

| 版本 | x86 成品 → 候选 | x64 成品 → 候选 |
| --- | ---: | ---: |
| 普通版 | 7,168 → **6,144 B** | 8,192 → **7,168 B** |
| Lite | 3,584 → 3,584 B | 4,096 → 4,096 B |
| Experimental | 2,042 → **2,038 B** | 2,441 → **2,421 B** |

### 普通版

**x64 可以分两步，各省 512 B。** 成品从两个 DLL 导入 40 个函数。导入查找表始于 RVA `0x3368`，导入地址表（IAT）始于 `0x34B8`。两表间相隔 336 B，恰好是 40 个地址和两个终止项。把全部 40 个函数接入 Lite 的 `compact_iat.inc`，共用一张表并复用导入名称的结尾，保留 CRT 的 Cookie 初始化和 CFG 默认入口，代码节仍为 4,038 B，合并资源的只读节从 3,344 降到 2,928 B。EXE 随之降到 **7,680 B**。

进一步使用项目已有的加载器 Cookie 和 Lite 的 CFG 默认入口，再将 `.pdata`、`.xdata` 都合入 `.text`。这时资源和常量占 2,480 B，代码连同展开数据占 4,084 B，分别装入 2,560 和 4,096 B，加上 512 B 文件头，成品为 **7,168 B**。只移动 `.pdata` 得到 7,680 B。仅在原版启用加载器 Cookie 则仍为 8,192 B。加载器方案将子系统版本设为 6.03，去掉了 CRT 初始化专用的两个导入，配置文件临时名使用的 `QueryPerformanceCounter` 仍保留。

**x86 先做节布局可到 6,656 B。** 一条路径沿用 CRT 初始化及全部 40 个导入。复用共享导入表，为普通版预留 792 B 资源树前缀，将两个 DLL 名共 24 B 放入代码节填充。这样只读数据和 376 B 重定位表合计恰好 2,560 B。另一条路径使用原有系统导入库，开启加载器 Cookie，合并资源树，并让 `compact-pe.ps1 -UseCodePadding` 将重定位表放入代码节，两条路径的 EXE 同为 6,656 B。

**x86 要到 6,144 B，还要把代码压进 3,072 B。** 组合共享导入、加载器 Cookie、Lite 的 CFG 默认入口和资源前缀，DLL 名使用常规只读位置。此时代码为 3,144 B。在 x86 的 LTO 链接阶段传入 `/mllvm:-disable-machine-licm` 和 `/mllvm:-x86-br-merging-base-cost=-1`，代码降为 3,080 B，仍超出 8 B。再让 x86 的 `IsMainKey` 复用 x64 已有的 32 B 位图，反汇编在 RVA `0x1105`、`0x179B`、`0x1A5E` 都生成了 `bt`。最终代码为 3,048 B，只读节为 2,548 B，分别只余 24 和 12 B。逐一核对了全部 256 个虚拟键的判定结果。

### Lite

在当前节布局中，下列数字表示单独缩小一个节、使成品再少一个 512 B 文件块所需的最小降幅。x86 代码节包括已放入其中的 148 B 重定位表。标准 PE 会按文件对齐值取整每个节的磁盘大小。[Microsoft PE 节表](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#section-table-section-headers)

| 架构 | 代码节有效长度 | 代码节需减 | 合并资源的只读节有效长度 | 只读节需减 |
| --- | ---: | ---: | ---: | ---: |
| x86 | 1,308 B | 284 B | 1,530 B | 506 B |
| x64 | 1,480 B | 456 B | 1,904 B | 368 B |

x64 的展开表显示，`Run` 占 505 B（RVA `0x104B`），`DialogProc` 占 613 B（RVA `0x1244`）。例如发送两个输入事件和补发一次释放时，RVA `0x1195` 和 `0x11BB` 两处各自准备 `SendInput` 的参数。单独抽出这个调用，x86 的代码节从 1,308 降到 1,292 B。x86 在 LTO 链接阶段调整上述两项分支及循环选项，代码节可到 1,276 B，EXE 仍为 3,584 B。

将读写文本和读取、设置勾选状态改用四个专用控件 API，x64 代码节减少 96 B，只读节增加 56 B，EXE 仍为 4,096 B。相同试验使 x86 EXE 从 3,584 **增至 4,096 B**。分别禁止内联 `Toggle`、`ReadInterval`、`SelectClickPair` 或 `Click`，两种架构也都没有省下文件块。下一轮适合把消息循环和回调放在一起精简，保留 Lite 的 `IsDialogMessageW` 导航、运行中控件锁定和中文资源，再按成品计量。

### Experimental

- **x86 省 4 B。** 窗口回调有两处相同的成功返回序列。让 `popad` 后的短跳转复用已有的 `push 1 / pop eax / ret 16`，文件末尾的代码节从 1,018 降到 1,014 B。
- **x64 省 20 B。** 三个鼠标按键标志可放入 IAT 前短文本已有的对齐空间。访问从 RIP 相对取表地址、再按索引读，变成一条 `movzx eax, byte ptr [rbx + rax - 0x3d]`，单项成品为 2,437 B。把只有一个调用点的错误消息框辅助函数并入入口，单项仍为 2,441 B。两项合用后代码节尾部从 1,417 降到 1,397 B，成品为 2,421 B。

**本轮验证。** 对五份普通版候选和两份 Experimental 候选核对了导入集合、加载配置、CFG 标志和重定位目录。普通版的对话框及管理员清单与发布版逐字节一致。Windows 10 22H2 隔离桌面实测了窗口创建、拒绝零间隔、60,000 ms 启停和正常关闭，普通版使用仅替换为 `asInvoker` 清单的测试副本。对最小的两份 x64 候选，`RtlVirtualUnwind` 从普通版 `Run`、`DialogProc` 及 Experimental 入口、回调的栈帧恢复了返回地址和寄存器。本轮没有实测实际鼠标事件、改键保存、Windows 11 或提权会话。候选仅用于体积分析。

### 接入发布预设后的复核

普通版在 `6f26498` 接入两个发布预设，Experimental 在 `ed5bd15` 采用上述回调和按键表改动。使用预设和 `pack.ps1 -IncludeExperimental` 打包后，四份成品与各自最小候选的差异仅为 COFF 时间戳，两份 Lite 与 v0.4.17 也仅有时间戳差异。六份打包文件的 SHA-256 均通过核对。两个架构另外构建了 `PICOCLICKER_STANDARD_LOADER_COOKIE=OFF` 的 CRT 路径，打包后与 v0.4.17 普通版逐字节比较也仅相差时间戳。

Windows 10 22H2 隔离桌面上，普通版和 Lite 使用仅修改清单的 `asInvoker` 副本，验证了无效间隔、启停、控件锁定、热键冲突和 `WM_QUIT` 退出码。普通版实测了改键保存、重启恢复、无效配置回退，以及 250／251 个 UTF-16 码元路径的保存边界。两份 Experimental 直接运行打包文件，通过单选按钮启动后读取进程中的一对 `INPUT`，分别核对了左、中、右键的按下和释放标志，并确认运行中改选不影响当前一对事件。
