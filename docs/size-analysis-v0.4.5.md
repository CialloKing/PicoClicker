# v0.4.5 之后的反汇编体积分析

基线为 v0.4.5（`92854bb`），候选代码为 `a86ee90`。四份基线 EXE 均通过该版本的 SHA-256 校验。使用同一套 clang-cl 22.1.8、LLD 22.1.8 和 Windows SDK 10.0.28000.0 重新构建，基线成品仅链接时间戳有差异。

| 版本 | 基线 EXE | 候选 EXE | 基线 → 候选 `.text` 有效字节 |
| --- | ---: | ---: | ---: |
| 普通 x64 | 8,704 | **8,192** | 4,390 → 4,086 |
| 普通 x86 | 7,168 | 7,168 | 3,496 → 3,432 |
| Lite x64 | 5,120 | 5,120 | 1,958 → 1,942 |
| Lite x86 | 4,096 | 4,096 | 1,464 → 1,464 |

普通 x64 的代码减少 304 字节，越过 4,096 字节边界，使磁盘上的代码节少占 512 字节。成品由 512 字节文件头、4,096 字节代码和 3,584 字节只读资源节组成。`.data` 的 1,184 字节由加载器零填充。

## 哪些改动有效

以下每项都单独应用于普通 x64 基线，再使用项目打包脚本测量。函数排列、分支距离和节对齐会随组合改变。

| 单项对照 | `.text` 减少字节 | 打包后 EXE |
| --- | ---: | ---: |
| 用 `BT` 在 32 字节位图中检查虚拟键 | 64 | 8,704 |
| 用 `REP MOVSW` 复制已知长度的 UTF-16 配置路径 | 32 | 8,704 |
| 一次比较 `WM_COMMAND` 的控件 ID 和通知码 | 32 | 8,704 |
| 复用启用控件的调用循环 | 16 | 8,704 |
| 将路径校验保留为独立函数 | 32 | 8,704 |
| 调整 LLVM 的循环不变量外提和条件分支合并两项设置 | 112 | 8,704 |
| 复用 192 字节的 x64 加载配置及其较小的支持代码 | 32 | 8,704 |
| 另写汇编叶函数，共享两处十六进制格式化 | 32 | 8,704 |
| 将共享的 `SendDlgItemMessageW` 换为四个专用控件 API | 64 | **9,216** |

四个专用控件 API 增加了导入数据，打包后的只读节从 3,572 增至 3,644 字节，越过 3,584 字节边界。候选保留共享的控件 API 和原有十六进制格式化。在候选上改用共享的 C 格式化函数或内联汇编，两种做法都得到 4,070 字节的代码节，EXE 均为 8,192 字节。x86 的按键范围判断仍能给只读节尾部的重定位表留出空间。

在候选普通 x64 的反汇编中，RVA `0x1154` 的 `bt dword ptr [rcx], edx` 检查队列消息中的主键，`0x1393` 的 `rep movsw` 复制路径，`0x151c` 和 `0x1529` 直接比较两个按钮的命令。可用 `llvm-objdump -d -M intel` 和 x64 构建目录的 `PicoClicker.map` 核对。Windows 将控件 ID 和通知码放在同一个参数的低字和高字中。[WM_COMMAND](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-command)

## 再省 512 字节需要多少

按候选的节布局计算，下表给出单独压缩某一节时，需要减少的有效字节数。不同节各有自己的 512 字节对齐边界。[PE 节表](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#section-table-section-headers)

| 版本 | 从 `.text` 省 | 从 `.rsrc` 省 |
| --- | ---: | ---: |
| 普通 x64 | 502 | **296** |
| 普通 x86 | 360 | 280 |
| Lite x64 | 406 | 448 |
| Lite x86 | 440 | 512 |

- 普通 x64 的 `.rsrc` 实占 3,368 字节。导入描述符、两套指针表、DLL 名和函数名等共占 1,494 字节，窗口与清单所在的完整资源树占 792 字节。下一轮可以先核对哪些 Win32 调用能复用，并把新增指令和减少的导入数据一起计量。
- 如果继续写汇编，普通 x64 的 `DialogProc` 和 `Run` 分别占 970 和 654 字节，边界来自 PE 展开表。优先比较这两处的消息分派、寄存器保存和调用准备。仅改写短小的格式化函数，在本次对照里最多省了几十字节。

## 验证范围

四份成品均通过打包校验。逐项核对导入函数、对话框和清单内容、重定位以及 x64 展开表。x64 实际加载后，CFG 调度指针已由系统填入，栈 Cookie 已初始化。按键位图的 256 个值逐个对照了原判断。

界面测试在后台隔离桌面运行，使用代码节与成品相同、清单设为 `asInvoker` 的副本。覆盖间隔校验、按钮启停、控件启用状态、F1 冲突、普通版改键与重启恢复，以及含非 BMP 字符的 250/251 个 UTF-16 码元配置路径边界。启停测试使用 60,000 ms 间隔，在首个定时信号前停止。实际鼠标事件、CPS 和管理员会话交互尚待复测。

## 实验版第二轮

以 `437f704` 为基线，使用 clang-cl 22.1.8、LLD 22.1.8 和 Windows SDK 10.0.28000.0。常规版和 Lite 的文件大小取打包成品，实验版取 `PicoClickerExperimental` 目标的输出。

| 版本 | EXE 字节 | `.text` 有效字节 |
| --- | ---: | ---: |
| 普通 x86 | 7,168 → 7,168 | 3,432 → 3,400 |
| 普通 x64 | 8,192 → 8,192 | 4,086 → 4,054 |
| Lite x86 | 4,096 → 4,096 | 1,464 → 1,416 |
| Lite x64 | 5,120 → 5,120 | 1,942 → 1,846 |
| 实验 x86 | 4,024 → **3,784** | 1,464 → 1,224 |
| 实验 x64 | 5,014 → **4,710** | 1,942 → 1,638 |

- 用一个计数器记录启停状态和代次。仅做这一项，Lite x86 的代码节少 32 字节，重定位表少 4 字节。按钮和 F1 复用切换路径，鼠标按钮检查复用控件消息调用。
- 把单个布尔辅助函数改为由调用点比较，两种架构的文件大小均持平。把退出进程移入消息循环虽然缩短了代码，却使编译器省掉 `Run` 的栈 Cookie 检查，因此保留原退出路径。
- 实验版将栈 Cookie 的磁盘初值放在只读数据中，使用 PE 子系统版本 6.03，由 Windows 加载器写入 Cookie。入口检查加载结果，无效时终止。实验版由此去掉了 CRT Cookie 初始化所需的四项导入，导入数从 27 降到 23。x86 的重定位表从 184 字节降至 156 字节。
- 上一版已裁掉 x86 的 72 字节末节填充。建议中的 3,944 字节是旧二进制扣除全部可数填充后的算术值，还需满足 Windows 的磁盘与内存映射约束。本轮 x86 达到 3,784 字节，主要收益来自实际代码和导入数据的减少。3,584 字节、3 KiB 与 2,500 字节仍是后续实验目标。

实验 x86 距 3,584 字节还差 200 字节。若保持现有标准布局，Lite x86 单独缩减代码节需要省 392 字节，单独缩减资源节需要省 508 字节，最终文件才会少一个 512 字节块。

四个常规产物通过发布打包检查。两种实验成品均使用 `asInvoker` 副本在 Windows 10 22H2 的隔离桌面验证界面、间隔校验、按钮启停和 F1 冲突。每种架构的两次启动都读到了不同的 Cookie，并确认 CFG 已启用、代码页可执行、可写数据页和资源页不可执行。x64 另外检查了 CFG 调度指针和异常展开表。

## 第三轮导入表和控件编号

本轮以 `e99a43a` 为基线，沿用上一轮工具链。控件编号从 1000–1006 改为 10–16，使部分 x86 的立即数指令变短。导入表在实验目标链接时生成。23 项按名称导入共享 IAT，省去独立 ILT 的 x86 100 字节、x64 200 字节。Hint/Name 条目复用前一个名称的结束字节，保持 Hint 字段的 2 字节对齐。加载器以名称核对 Hint 的结果。[Microsoft PE 导入表规范](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#the-idata-section)

| 实验版 | 上轮 EXE | 仅控件编号 | 完成导入表优化 | 只读资源节有效字节 |
| --- | ---: | ---: | ---: | ---: |
| x86 | 3,784 | 3,736 | **3,736** | 1,896 → 1,752 |
| x64 | 4,710 | 4,710 | **4,198** | 2,288 → 2,040 |

x64 的只读节越过 2,048 字节对齐边界，整个 EXE 少占 512 字节。x86 的只读节在两次测量中均占四个 512 字节块，体积收益来自代码节。当前实验 x86 距 3.5 KiB 还差 152 字节。

`PICOCLICKER_STANDARD_LOADER_COOKIE` 可单独应用于标准布局的普通版和 Lite。启用后普通版从 40 项导入降到 38 项，Lite 从 27 项降到 23 项。四种构建均通过标准打包，代码与只读数据的缩减尚未跨过各自的文件对齐边界。

| 标准布局 | 打包后字节 | 上轮 `.text` | 当前默认 `.text` | 启用加载器 Cookie 的 `.text` |
| --- | ---: | ---: | ---: | ---: |
| 普通 x86 | 7,168 | 3,400 | 3,352 | 3,144 |
| 普通 x64 | 8,192 | 4,054 | 4,038 | 3,830 |
| Lite x86 | 4,096 | 1,416 | 1,368 | 1,176 |
| Lite x64 | 5,120 | 1,846 | 1,830 | 1,638 |

在 Windows 10 22H2 的隔离桌面上，用 `asInvoker` 副本验证了界面、间隔校验、启停和 F1 冲突。普通版另外验证了改键、保存和重启恢复。两个实验版分别核对了 23 个运行时导入地址、CFG、Cookie 和各节权限。对启用加载器 Cookie 的四个标准产物也读取了运行时 Cookie。管理员会话、其他 Windows 版本及安全软件兼容性待验证。

## 实验版 ASCII 界面

本轮以 v0.4.6 发布资产为基线。实验版使用英文控件文字、ASCII 运行时文本和七项 ANSI Win32 导入。导入名的 `A` 与 `W` 后缀等长，主要收益来自短状态文本、单字节数字缓冲区和共用错误提示调用。标准对话框模板以 UTF-16 保存英文标签。[Microsoft 对话框模板规范](https://learn.microsoft.com/windows/win32/api/winuser/ns-winuser-dlgtemplate)

| 实验版 | EXE 字节 | `.text` 有效字节 | 只读资源节有效字节 |
| --- | ---: | ---: | ---: |
| x86 | 3,736 → **3,732** | 1,176 → 1,176 | 1,752 → 1,684 |
| x64 | 4,198 → **4,182** | 1,638 → 1,622 | 2,040 → 1,976 |

x86 将只读节放在文件末尾再裁剪。x64 将代码节放在末尾。只读数据节省的大部分字节落在既有对齐空间内。普通版和 Lite 的四份打包成品与 v0.4.6 逐字节一致，差异仅为链接时间戳。

Windows 10 22H2 的隔离桌面验证了两种实验版的 1、10、50 ms 档左中右键事件、F1 启停、热键冲突和运行中关闭，并检查了加载器 Cookie、CFG、运行时导入地址及各节权限。测试使用仅将清单改为 `asInvoker` 的副本。间隔解析检查控件返回的 ASCII 字节。在 ANSI 代码页 936 上，Windows 将外部传入的 `5000²` 转成 `50002`，程序按界面显示的数字处理。

## 汇编与重定位布局

以 `45503b9` 的 ASCII 实验版为基线，继续用 clang-cl 和 LLD 22.1.8 构建。下表的代码字节取链接后的 `.text`，打包时移入同一节的重定位表另列。

| 实验版 | EXE 字节 | 代码节有效字节 | 基址重定位表 | 打包后只读资源节有效字节 |
| --- | ---: | ---: | ---: | ---: |
| x86 | 3,732 → **3,300** | 1,176 → 1,128 | 152 → 124 | 1,684 → 1,512 |
| x64 | 4,182 → **4,134** | 1,622 → 1,574 | 20 → 20 | 1,976 → 1,944 |

- 将 x86 基址重定位表从只读节末尾搬到代码节原有的填充区，单独让成品从 3,732 降到 3,376 字节。资源节因此占 1,536 字节，代码节放在文件末尾。最终代码节在磁盘上占 1,252 字节，其中 124 字节是重定位表。节的 RVA、页面对齐和权限标志沿用原布局。[Microsoft PE 基址重定位表](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#the-reloc-section-image-only)
- x86 汇编通过一个寄存器和短偏移访问 IAT，消息队列读完后复用缓冲区读取光标位置。仅替换等待与点击路径时，代码和重定位分别减少 32 和 24 字节，成品为 3,320 字节。改用汇编实现整个启停函数的对照多占 8 字节。
- 实验版退出时由系统回收固定的 F1 注册，导入数从 23 降到 22。尝试改用关闭标记代替 `PostQuitMessage` 时，两种架构的 C 候选各增大 32 字节。x64 在保留当前消息循环结构的前提下单独关闭机器循环不变量外提，再省 32 字节。

四份普通版和 Lite 的打包成品在归一化链接时间戳后与 v0.4.6 逐字节一致。Windows 10 22H2 隔离桌面的实验副本经过了实际点击、F1 冲突及关闭后重新注册、`WM_QUIT` 退出码和栈 Cookie 检查，并在非首选基址核对了 CFG、IAT 和内存页权限。本轮实际点击使用只改动清单的 `asInvoker` 副本。

同桌面交替测试 1 ms 档，每次采样约 1.2 秒。x86 优化前后三次样本分别为 544–558 CPS 和 522–558 CPS，间隔 P99 分别为 6.89–7.56 ms 和 6.76–9.16 ms。x64 单次对照从 532 到 550 CPS，间隔 P99 从 7.65 到 7.13 ms。x86 两组范围重叠，短测不足以确认性能是否回退。
