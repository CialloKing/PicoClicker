# v0.4.5 之后的反汇编体积分析

基线为 v0.4.5（`92854bb`），候选代码为 `a86ee90`。四份基线 EXE 均通过该版本的 SHA-256 校验。使用同一套 clang-cl 22.1.8、LLD 22.1.8 和 Windows SDK 10.0.28000.0 重新构建，基线成品仅链接时间戳有差异。

| 版本 | 基线 EXE | 候选 EXE | 基线 → 候选 `.text` 有效字节 |
| --- | ---: | ---: | ---: |
| 普通 x64 | 8,704 | **8,192** | 4,390 → 4,086 |
| 普通 x86 | 7,168 | 7,168 | 3,496 → 3,432 |
| Lite x64 | 5,120 | 5,120 | 1,958 → 1,942 |
| Lite x86 | 4,096 | 4,096 | 1,464 → 1,464 |

普通 x64 的代码减少 304 字节，越过 4,096 字节边界，使磁盘上的代码节少占 512 字节。成品由 512 字节文件头、4,096 字节代码和 3,584 字节只读资源节组成。`.data` 的 1,184 字节由加载器零填充。

## 哪些改动有效

以下每项都单独应用于普通 x64 基线，再使用项目打包脚本测量。函数排列、分支距离和节对齐会随组合改变。

| 单项对照 | `.text` 减少字节 | 打包后 EXE |
| --- | ---: | ---: |
| 用 `BT` 在 32 字节位图中检查虚拟键 | 64 | 8,704 |
| 用 `REP MOVSW` 复制已知长度的 UTF-16 配置路径 | 32 | 8,704 |
| 一次比较 `WM_COMMAND` 的控件 ID 和通知码 | 32 | 8,704 |
| 复用启用控件的调用循环 | 16 | 8,704 |
| 将路径校验保留为独立函数 | 32 | 8,704 |
| 调整 LLVM 的循环不变量外提和条件分支合并两项设置 | 112 | 8,704 |
| 复用 192 字节的 x64 加载配置及其较小的支持代码 | 32 | 8,704 |
| 另写汇编叶函数，共享两处十六进制格式化 | 32 | 8,704 |
| 将共享的 `SendDlgItemMessageW` 换为四个专用控件 API | 64 | **9,216** |

四个专用控件 API 增加了导入数据，打包后的只读节从 3,572 增至 3,644 字节，越过 3,584 字节边界。候选保留共享的控件 API 和原有十六进制格式化。在候选上改用共享的 C 格式化函数或内联汇编，两种做法都得到 4,070 字节的代码节，EXE 均为 8,192 字节。x86 的按键范围判断仍能给只读节尾部的重定位表留出空间。

在候选普通 x64 的反汇编中，RVA `0x1154` 的 `bt dword ptr [rcx], edx` 检查队列消息中的主键，`0x1393` 的 `rep movsw` 复制路径，`0x151c` 和 `0x1529` 直接比较两个按钮的命令。可用 `llvm-objdump -d -M intel` 和 x64 构建目录的 `PicoClicker.map` 核对。Windows 将控件 ID 和通知码放在同一个参数的低字和高字中。[WM_COMMAND](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-command)

## 再省 512 字节需要多少

按候选的节布局计算，下表给出单独压缩某一节时，需要减少的有效字节数。不同节各有自己的 512 字节对齐边界。[PE 节表](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#section-table-section-headers)

| 版本 | 从 `.text` 省 | 从 `.rsrc` 省 |
| --- | ---: | ---: |
| 普通 x64 | 502 | **296** |
| 普通 x86 | 360 | 280 |
| Lite x64 | 406 | 448 |
| Lite x86 | 440 | 512 |

- 普通 x64 的 `.rsrc` 实占 3,368 字节。导入描述符、两套指针表、DLL 名和函数名等共占 1,494 字节，窗口与清单所在的完整资源树占 792 字节。下一轮可以先核对哪些 Win32 调用能复用，并把新增指令和减少的导入数据一起计量。
- 如果继续写汇编，普通 x64 的 `DialogProc` 和 `Run` 分别占 970 和 654 字节，边界来自 PE 展开表。优先比较这两处的消息分派、寄存器保存和调用准备。仅改写短小的格式化函数，在本次对照里最多省了几十字节。

## 验证范围

四份成品均通过打包校验。逐项核对导入函数、对话框和清单内容、重定位以及 x64 展开表。x64 实际加载后，CFG 调度指针已由系统填入，栈 Cookie 已初始化。按键位图的 256 个值逐个对照了原判断。

界面测试在后台隔离桌面运行，使用代码节与成品相同、清单设为 `asInvoker` 的副本。覆盖间隔校验、按钮启停、控件启用状态、F1 冲突、普通版改键与重启恢复，以及含非 BMP 字符的 250/251 个 UTF-16 码元配置路径边界。启停测试使用 60,000 ms 间隔，在首个定时信号前停止。实际鼠标事件、CPS 和管理员会话交互尚待复测。
